# Version 3.15.1 — latence Operon

Cette version raccourcit les appels Operon côté MCP. Les reçus de mutation n’attendent plus le rafraîchissement complet du snapshot, `operon_get_task` lit une seule tâche quand le snapshot est en retard, et un rafraîchissement enchaîne moins d’appels Bridge. Voir le [changelog](../../CHANGELOG.md#3151---2026-10-27) et les [suites de l’audit](../audit-followups-20261027.md), section 6.

Aucun changement de Bridge : conserver Atomic Write Bridge 0.8.5 et Operon Bridge 0.9.3. L’installer comme la 3.15.0, en paire avec Atomic Write Bridge 0.8.5.

Si l’index se stabilise encore juste après une mutation (par exemple quand un second écrivain comme un gestionnaire de dates retouche la note), la lecture suivante l’attend jusqu’à 15 secondes au lieu de rendre le snapshot précédent.

Garanties conservées : un reçu n’affirme que ce que le Bridge a prouvé ; chaque lecture déclare `source`, `stale` et `snapshotAt` ; une lecture faite après un reçu dans le même processus voit cette mutation. Les gains mesurés viennent d’un coffre de test de 159 tâches et ne constituent pas un engagement de service. Il reste environ 0,7 s par appel Bridge, passées dans la renégociation de session Operon du Bridge ; seule une version du Bridge peut les supprimer.
