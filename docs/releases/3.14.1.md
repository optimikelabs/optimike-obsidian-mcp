# Version 3.14.1 — semantic search parity

Prepared on October 23, 2026. This patch release brings the semantic cache and Smart Environment reader in line with the runtime qualified locally since October 8, 2026. No Bridge code changes.

- Smart Environment v3 vectors are validated against the source's `last_read.hash`, with `last_import.hash` as the fallback for import-only records. Notes re-embedded without a new import stay searchable; missing or stale hashes are still rejected.
- The private semantic vector cache stores exact little-endian Float64 values in base64 instead of decimal JSON. Historical number arrays remain readable. A versioned source signature makes old and new releases rebuild the derived cache from Smart Connections sources once, after an upgrade or a rollback; the first semantic query afterwards is slower.
- A semantic query and a readiness probe already in flight in the same refresh generation share one source read. Concurrent probes are coalesced, a successful observation is kept for at most 60 seconds, source files are checked in bounded batches of 32 and an unchanged in-memory snapshot is reused. Probes never write the cache.
- A semantic probe that exceeds its deadline reports `semantic_probe_timed_out` with `retry_capability_probe`, distinct from a missing index. The capability remains unavailable and unauthorized; a late result never promotes it.

MCP 3.14.1 keeps Atomic Write Bridge 0.8.2, Operon Bridge 0.9.3 and Bases Bridge 1.2.2.

Local measurements on a frozen corpus of 7,578 vectors (October 8, 2026): cache persistence 5.45 to 2.50 s, vector payload 102.0 to 52.2 MB, cold query plus diagnostic 11.0 / 8.2 s to 4.9 / 4.8 s depending on which starts first. They are not an SLA; no RAM reduction is claimed.

See the [cache encoding contract](../semantic-vector-cache-encoding.md).
