# Version 3.16.0 — création gouvernée de Bases et de Canvas

Un agent peut maintenant créer une Base ou un Canvas dans un coffre live par un cycle gouverné, comme il crée déjà une note. Avant cette version, `bases_create` était refusé par le Bases Bridge dans sa configuration par défaut, et aucun outil MCP ne pouvait créer de Canvas hors du mode `headless-filesystem`.

- `bases_create_plan` → `bases_create_apply` → `bases_create_status` créent un nouveau fichier `.base`.
- `obsidian_canvas_create_plan` → `obsidian_canvas_create_apply` → `obsidian_canvas_create_status` créent un nouveau fichier `.canvas`.

Le plan valide le contenu et le scelle ; apply crée le fichier seulement s’il est toujours absent, ne l’écrase jamais et ne crée jamais son dossier ; status confirme les octets exacts. Un Canvas créé a un graphe valide : `obsidian_canvas_patch_plan` peut le modifier ensuite. Voir la [création gouvernée de Bases et de Canvas](../governed-file-create.fr.md) et le [changelog](../../CHANGELOG.md#3160---2026-10-28).

## Installation

Installer ensemble le MCP 3.16.0 et le bundle des Bridges de la même release : il livre Atomic Write Bridge 0.9.0, Operon Bridge 0.9.3 et Bases Bridge 1.2.2 (seul l’Atomic Write Bridge change). Vider d’abord les opérations en attente, comme pour la 3.15.

Ensuite, seulement là où vous le voulez, activer **Autoriser la création exclusive de Bases** et/ou **Autoriser la création exclusive de Canvas** dans les réglages de l’Atomic Write Bridge. Les deux sont désactivés par défaut ; le serveur exige aussi `MCP_WRITE_MODE` `guarded` ou `full`. Les outils apparaissent dans les profils `authoring`, `operational` et `full`.

## Hors périmètre

- La modification des vues ou des filtres d’une Base existante (les formules et les propriétés des notes gardent leurs familles gouvernées).
- La reprise ou l’annulation : une création incertaine s’observe avec status et, après examen, se clôt avec `obsidian_operation_close`.
