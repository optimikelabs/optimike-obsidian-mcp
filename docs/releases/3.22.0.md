# Version 3.22.0 — Base formulas checked by Obsidian's own engine

3.22.0 lets agents check Base formulas and Markdown against what Obsidian actually does, instead of against a copy of its rules.

- **Obsidian's Bases engine through the Bases Bridge (PR #178):** `POST /extensions/obsidian-bases-bridge/engine/evaluate` runs every formula of a Base, as stored or as an in-memory candidate, with Obsidian's own engine and reports `ok`, `syntax_error`, `runtime_error`, `all_null` or `not_evaluated` per formula. A good and a bad canary formula are checked on each call; if they misbehave, the answer is `available: false`. `GET .../engine/functions` returns the formula functions of the installed Obsidian, read from the running app.
- **`bases_query` computed by the engine (PR #179):** with `evaluate` (default), rows, view filters, sort, limit and formula values come from Obsidian (`source: "engine"`), including formulas the old Bridge evaluator could not compute, such as `link(file, file.name)`. Without the engine, `source: "fallback"` returns no formula value instead of a guessed one. The Bridge's private formula evaluator is removed.
- **Base plans refused before sealing (PR #181):** `bases_formula_patch_plan` and `bases_config_patch_plan` evaluate the Base as stored and as planned. A plan that turns a formula into a syntax or runtime error is refused with `base_formula_engine_error`; nothing is sealed or written, and `formulaCheck` gives the engine messages, the unknown functions, the valid functions for the type and close names (`lowr` suggests `lower`). Errors already present do not block; an always-empty formula is a warning. The receipt carries `engineCheck`: `verified` with the Obsidian version, or `unverified` with a reason.
- **`bases_functions` and `bases_check` (PR #182, issue #176):** read-only. `bases_functions` lists the formula functions of the installed Obsidian by type, or the signatures of one type. `bases_check` reports the formula health of one Base or of every Base; an unavailable engine, a closed Obsidian or a missing Bases Bridge is `unverified`, never healthy.
- **`obsidian_validate_format` checks Markdown against the open vault (PR #180, issue #177):** with Atomic Write Bridge 0.10.0, links and embeds that resolve to no file, missing headings and block ids, callout types unknown to Obsidian, the theme and CSS snippets, and property values against their declared types. Only issues the content adds to the current file are reported. Code is skipped, including fenced code inside blockquotes and callouts and indented code blocks. Without the Bridge, the static checks stand and `vaultCheck` says the vault was not checked.

Checked live on a disposable vault with Obsidian 1.15.1: engine answers in 3 to 150 ms per call (the 150 ms is `bases_check` over 10 Bases); the refused plans left the Base byte for byte unchanged; a test note with seven problems returned all seven, and an existing note reread unchanged returned none.

**Bridges:** Bases Bridge 1.3.0 and Atomic Write Bridge 0.10.0 ship in the bundle of this release; Operon Bridge 0.9.9 is unchanged. Install the MCP and the Bridge bundle of the same release together, Obsidian closed (see [Bridge packaging](../bridge-packaging.md)). With older Bridges the new checks answer `unverified` or skip the vault check; nothing breaks. See the [changelog](../../CHANGELOG.md#3220---2026-11-20).
