# Version 3.14.0 — date preparation

Published on October 23, 2026. This version includes fixes [#122](https://github.com/optimikelabs/optimike-obsidian-mcp/pull/122) and [#124](https://github.com/optimikelabs/optimike-obsidian-mcp/pull/124).

- A note without `création` is dated by the date manager before a protected modification plan is sealed. FDM remains the author of dates; the MCP does not calculate them. The requested modification still waits for `apply`.
- Templates under `X/Modèles/**`, the configured Templater folder and paths excluded by FDM remain undated: this workflow neither requires nor adds dates to them. FDM exclusions and their exceptions are respected.
- Without an active date manager, preparation is clearly refused: the user is asked to open the note in Obsidian, save it once and retry.
- CRLF/LF line endings normalized by Obsidian during date preparation are accepted, including mixed files. The receipt reports normalization. Changes to text, spaces, the number of line breaks or non-date properties remain conflicts; CAS keeps the exact hash of the fresh read after preparation.

MCP 3.14.0 and Atomic Write Bridge 0.8.2 must be installed together. The bundle retains Operon Bridge 0.9.3 and Bases Bridge 1.2.2.

Date preparation and template protection are qualified with FDM 1.6.0; other date managers are not qualified. This qualification does not guarantee against later independent modifications. Preparation may date the note during `plan`, before `apply`. If an already dispatched FDM command completes after a timeout, reread the note before retrying.

Security: update `follow-redirects` to 1.16.1 to fix credential-header exposure risks during redirects (#123).
