# Version 3.16.0 — governed Base and Canvas creation

An agent can now create a Base or a Canvas in a live vault through a governed lifecycle, as it already creates a note. Before this release, `bases_create` was refused by the Bases Bridge in its default configuration, and no MCP tool could create a Canvas outside the `headless-filesystem` mode.

- `bases_create_plan` → `bases_create_apply` → `bases_create_status` create one new `.base` file.
- `obsidian_canvas_create_plan` → `obsidian_canvas_create_apply` → `obsidian_canvas_create_status` create one new `.canvas` file.

The plan validates the content and seals it; apply creates the file only if it is still absent, never overwrites it and never creates its folder; status confirms the exact bytes. A created Canvas has a valid graph, so `obsidian_canvas_patch_plan` can edit it afterwards. See [governed Base and Canvas creation](../governed-file-create.md) and the [changelog](../../CHANGELOG.md#3160---2026-10-28).

## Install

Install MCP 3.16.0 and the Bridge bundle of the same release as one pair: it ships Atomic Write Bridge 0.9.0, Operon Bridge 0.9.3 and Bases Bridge 1.2.2 (only the Atomic Write Bridge changes). Drain pending operations first, as for 3.15.

Then, only where you want it, enable **Allow exclusive Base creation** and/or **Allow exclusive Canvas creation** in the Atomic Write Bridge settings. Both are off by default; the server also needs `MCP_WRITE_MODE` `guarded` or `full`. The tools appear in the `authoring`, `operational` and `full` profiles.

## Not included

- Editing the views or filters of an existing Base (formulas and note properties keep their governed families).
- Recovery or undo: an uncertain creation is observed with status and, after review, closed with `obsidian_operation_close`.
