# Version 3.15.2 — Operon reads after an outage

This release corrects two limits of 3.15.1 found in review. See the [changelog](../../CHANGELOG.md#3152---2026-10-27) and [audit follow-ups](../audit-followups-20261027.md), section 6.

No Bridge changes: keep Atomic Write Bridge 0.8.5 and Operon Bridge 0.9.3. Install it like 3.15.1, as one pair with Atomic Write Bridge 0.8.5.

- When Obsidian or the Bridge is gone (connection refused, no HTTP answer), a read no longer waits: it answers at once from the persisted snapshot, marked stale, with the missing-mutation limitation. Retries remain for transient failures only (index settling or moving, Bridge 503), within 15 seconds including the last attempt, once per pending mutation, and they stop when the client cancels the request.
- A stale fallback reloads the persisted snapshot first, so it returns the newest committed state.

Guarantee: a read made after a receipt in the same process either sees that mutation, or is marked `operon-cache` / `stale: true`; while the mutation is still uncovered, that fallback adds a limitation stating that it misses a confirmed mutation. Across processes or after a backend restart, only the index generation protects, as in 3.15.0.
