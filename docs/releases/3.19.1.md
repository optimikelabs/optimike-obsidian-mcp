# Version 3.19.1 — Refusals that say why

3.19.1 makes Operon and governed text patch refusals readable, so that an agent fixes its request instead of blaming the Bridge or Operon (issue #152).

- **Reused idempotency key:** applying with the key of the dry-run was refused by the MCP mutation journal with a generic `CONFLICT`, and agents concluded to a Bridge/Operon incompatibility. The refusal now carries `reasonCode: idempotency_key_reused`, `retryable: false` and an action: this call applied nothing; if the earlier request was only the dry-run, apply with a new key, otherwise check its result first. The descriptions of the dry-run Operon mutation tools state the rule: one key for the dry-run, a new one for the apply.
- **Uncertain outcomes say so on the first refusal:** a lost journal reservation after an apply, a final task identity or postcondition that does not match, or an earlier in-progress attempt with the same key now return `operon_mutation_outcome_uncertain` with `mutationMayHaveApplied: true`: read the task before deciding, never retry with a new key. Refusals while Operon's index or settings are moving return `operon_index_not_settled` (`retryable: true`).
- **Operon Bridge 0.9.8:** `idempotency_key_reused`, `source_line_conflict` and `interrupted_in_progress` no longer collapse into `bridge_error` ("could not be completed"). A native failure receipt that may have applied now reads `outcome_unverified` with a read-before-retry instruction, including over HTTP where receipts are filtered twice. In one production vault, 34 of 69 Operon failure receipts carried `bridge_error`, 8 of them creations that may have applied.
- **Governed text patch:** compiler refusals now say why instead of "The request could not be validated.", for example `task_line_touched` (a text patch never edits a `- [ ]` task line: use the `operon_*` tools), `literal_not_found` and `literal_not_unique`. The sealed text is never echoed.
- **Unchanged:** unknown codes stay masked; no request data, key, path or task text is returned. Closed Bridge codes received over HTTP keep the Bridge's boolean `retryable` (today only the saved-filter query uses that path; mutations return structured receipts).

Install MCP 3.19.1 with the Bridge bundle of the same release (Operon Bridge 0.9.8, Atomic Write Bridge 0.9.2, Bases Bridge 1.2.2). No setting, grant or contract change for clients beyond new public `reasonCode` values. Follow-ups: #154 (per-phase idempotency keys), #155 (one refusal envelope and a shared code registry), #156 (refusal observability). See the [changelog](../../CHANGELOG.md#3191---2026-11-06).
