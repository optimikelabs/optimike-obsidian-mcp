# Version 3.23.0 — Agents find the right Obsidian tool, and can ask before writing

3.23.0 helps agents that load tools by search find this server's tools before another server's, and lets a client ask a native yes/no question before a governed text patch is written.

- **Search hints on 32 entry points (PR #191, issue #190):** note, Base and canvas reads, governed `*_plan` tools and Operon task tools carry a short `_meta["anthropic/searchHint"]` with the user's words their name lacks (for example `operon_transition_task`: "mark done, complete, cancel, reopen, change status"). Hints go on plans, never on apply, status or recover steps. Tool names, descriptions, input schemas, annotations, profiles and capability claims are unchanged; clients that do not know the key ignore it. On 78 blind held-out keyword queries ranked like Claude Code 2.1.331, the expected tool is in the top 3 for 57 instead of 46, and first for 47 instead of 27. In real Claude Code runs the final tool was correct in 144 of 156 runs, against 127 of 152 before. Codex filters tools in its own code and never reads `_meta`: unchanged.
- **Server instructions that ask for the word `obsidian` (PR #194, issue #192):** the MCP instructions now always open with one sentence asking the client to include `obsidian` in its tool searches, because other connected servers may have tools with the same verbs (`add_note`, `update_task`). The vault-instructions paragraph follows unchanged; a client that got no instructions before now gets this sentence alone. Next to replayed Rize, Brevo, Claude Docs and T3 catalogues, over 64 Claude Code runs: right final tool 61 → 63, another server's writing tool chosen 3 → 1, searches containing `obsidian` 7/43 → 57/63, no case correct before and wrong after. The word helps through the configured server name and the `obsidian_*` tool names: keep `obsidian` in the server key, as in `optimike-obsidian-mcp-stdio`. See [Tool Surface Profiles](../tool-surface-profiles.md).
- **Optional apply confirmation (PR #189, issue #188):** off by default. With `MCP_PROTOCOL_MODE=dual` and `MCP_APPLY_CONFIRMATION=elicit`, `obsidian_text_patch_apply` asks the client a yes/no question before writing, if the client declares form elicitation. The question names the target, operation kinds, changed frontmatter keys and the `planRef`, never the sealed text. Accept applies the exact sealed plan under the usual CAS and the receipt adds `confirmation: "elicited"`; decline answers `apply_confirmation_declined`, nothing is written and the plan stays `planned`, so applying it again asks again. Cancel, an invalid or expired answer, a client or relay error and a note changed since planning are closed refusals too. An accept can come from a host hook, so it never claims a person clicked. Behind the stdio proxy both the proxy and the backend need the setting. See [Optional apply confirmation](../governed-text-patch-p4.md#optional-apply-confirmation-elicitation).
- **Tool discovery eval (PR #191):** `evals/tool-discovery-corpus.json` and `scripts/run-tool-discovery-eval.mjs` reproduce the Claude Code ranking without a model, run real Claude Code and isolated Codex sessions against a catalogue-only replay server that refuses every tool call, and can serve other servers' catalogues next to it. See [tool-routing evals](../../evals/README.md).
- **Repository:** the LICENSE header lists the current copyright holder first (PR #186), and CI skips the runtime suites for LICENSE- or NOTICE-only changes while still reporting the required checks (PR #187).

The measurements ran on a synthetic empty vault with replayed catalogues and no tool executed; samples are small (2 runs per case for Claude Code), so the change in search wording is the robust signal. Not verified: a real host's elicitation card, and clients that ignore MCP server instructions (they see no change).

**Bridges:** no Bridge change. Atomic Write Bridge 0.10.0, Operon Bridge 0.9.9 and Bases Bridge 1.3.0 ship unchanged in the bundle of this release: upgrading from 3.22.0 needs no Bridge reinstall. See the [changelog](../../CHANGELOG.md#3230---2026-11-25).
