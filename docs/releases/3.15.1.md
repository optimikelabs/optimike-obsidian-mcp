# Version 3.15.1 — Operon latency

This release shortens Operon calls on the MCP side. Mutation receipts no longer wait for the full snapshot refresh, `operon_get_task` reads a single task when the snapshot is behind, and a refresh makes fewer sequential Bridge calls. See the [changelog](../../CHANGELOG.md#3151---2026-10-27) and [audit follow-ups](../audit-followups-20261027.md), section 6.

No Bridge changes: keep Atomic Write Bridge 0.8.5 and Operon Bridge 0.9.3. Install it like 3.15.0, as one pair with Atomic Write Bridge 0.8.5.

Guarantees kept: a receipt states only what the Bridge proved; every read declares `source`, `stale` and `snapshotAt`; a read made after a receipt in the same process sees that mutation. The measured gains come from a test vault with 159 tasks and are not an SLA. About 0.7 s per Bridge call remains, spent in the Bridge's Operon session renegotiation; only a Bridge release can remove it.
