# Version 3.21.0 — Semantic search that returns the section that answers

3.21.0 lets `smart_semantic_search` return the heading sections and paragraphs that answer a query, with their verified line range, instead of only whole notes (PR #169, hardened by #171).

- **`granularity`:** `notes` (default, result shape unchanged), `sections`, or `both` (notes and sections ranked together). A section result gives the note `path`, `block_key`, `headings`, `lines` `[start, end]` (1-based, inclusive) and `score`; with `with_snippets`, the text of those lines (at most 1,200 characters). The `folders` and `tags` filters apply to the note of each section.
- **Vectors Smart Connections already computes:** sections use the block vectors of the active model in `.smart-env/smart_blocks/<model fingerprint>`, with the same freshness rule as notes (`read_hash` equal to `last_read.hash`). Frontmatter blocks are skipped. They are read in the same pass over the source records as note vectors, kept in one float32 array, and loaded on the first section query only; the shared store keeps their references, not the vectors.
- **Lines checked against the note as it reads now:** the block content hash proves that the lines hold the embedded text; a section moved by an edit above is found again (`lines_verified: true`), a rewritten one returns its indexed lines with `lines_verified: false` and no snippet. The search for a moved section is bounded per request and never looks past the end of the note. On a real vault of 6,889 notes, 16 % of 44,924 sections had moved since indexing.
- **Clear refusal:** without block vectors of the active model, a section search answers `semantic_sections_unavailable` before embedding the query.

Measured on that vault (640 dimensions): the first cold load of notes and sections takes 7.7 to 8.2 s, a load from the shared store 0.45 to 0.56 s, section ranking 50 to 85 ms per query, and sections add about 123 MB of resident memory once a section query has run.

The Bridges are unchanged (Atomic Write Bridge 0.9.2, Operon Bridge 0.9.9, Bases Bridge 1.2.2): upgrading from 3.20.0 needs no Bridge reinstall. Follow-up noted in PR #169: a direct test for absurd block row indexes (the code already skips them). See the [changelog](../../CHANGELOG.md#3210---2026-11-16).
