# Version 3.23.1 — Antigravity charge le catalogue, Codex trouve l'outil d'échéance

La 3.23.1 corrige un schéma qui empêchait Antigravity de charger le moindre outil de ce serveur, et reformule deux descriptions Operon pour les clients qui choisissent leurs outils en lisant noms et descriptions, comme Codex.

- **Curseur compatible avec Antigravity (PR #197) :** Antigravity 1.5.12 ne savait pas compiler la répétition `{1,2048}` du motif `cursor` de `obsidian_list_pending_operations` ; il refusait alors toute la boîte à outils et aucune demande n'arrivait au modèle. Le motif publié est maintenant `^[A-Za-z0-9_-]+$` ; le serveur refuse toujours un curseur de plus de 2048 caractères ou hors de cet alphabet. Seul ce motif change dans le catalogue de 104 outils. Antigravity 1.5.12 liste maintenant le catalogue et choisit le bon outil pour 85 demandes rejouées sur 104 ; Claude Code et Codex reçoivent le même catalogue qu'avant.
- **Descriptions d'échéance et de récurrence (PR #198) :** `operon_update_task` commence maintenant par le changement d'échéance (`dateDue`) ou d'autres champs d'une tâche existante, et `operon_update_recurrence` par la règle d'une tâche qui se répète. Codex ne lit jamais `_meta["anthropic/searchHint"]` et ne profitait donc pas des indices de la 3.23.0 : sur les demandes « décale l'échéance », Codex CLI et Codex dans T3 passent de 0 sur 4 à 4 sur 4. Sur 104 demandes rejouées : Codex CLI 100 → 104, Codex dans T3 99 → 103, Claude Code 104 → 104, Mistral Vibe 87 → 89, Antigravity 85 → 86. Seules ces deux descriptions changent ; schémas, indices, instructions, profils et contrôles sont inchangés.
- **Évaluation de la découverte (PR #196) :** le nom exact d'un outil dans un cas du corpus est résolu avant les alias, si bien qu'un cas ne peut plus être noté contre le mauvais outil.

Ce sont des comparaisons sur un seul passage, contre un serveur de rejeu qui refuse tout appel d'outil. Un test A/A avec le même catalogue des deux côtés a inversé 8 paires sur 28 : un écart d'une réponse par cas relève du bruit. Les deux cas qui s'étaient dégradés ont été rejoués 8 fois de chaque côté avant la fusion (Codex dans T3 : 8/8 contre 8/8 ; création de Canvas dans Mistral Vibe : 5/8 contre 6/8).

**Bridges :** aucun changement de Bridge. Atomic Write Bridge 0.10.0, Operon Bridge 0.9.9 et Bases Bridge 1.3.0 sont livrés inchangés dans le bundle de cette release : passer de la 3.23.0 ou de la 3.22.0 à la 3.23.1 ne demande pas de réinstaller les Bridges. Voir le [changelog](../../CHANGELOG.md#3231---2026-11-26).
